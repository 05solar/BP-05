## 1. 서론

### 1.1 연구 배경

천적생물방제(biological control)는 화학 농약 사용을 최소화하면서 해충 개체군을 자연적으로 억제하는 친환경 농업 기술이다. 전북특별자치도농업기술원은 천적생물의 대량 증식·공급 기술을 연구하고 있으며, 천적응애(predatory mite)를 흙과 유사한 배지에서 사육하고 주기적으로 먹이응애를 공급하여 약 2~4주간 증식시킨 뒤 친환경 농가에 공급한다.

공급 품질을 보장하기 위해서는 출하 전 개체 수와 활력도를 정확히 평가하여야 한다. 그러나 기존 검사는 연구원이 현미경으로 개체를 직접 계수하고 활력도를 육안으로 판정하는 수작업에 의존하였다. 이 방식은 샘플 수가 증가할수록 검사 시간이 급증하며, 작업자의 숙련도·피로도·주관적 판단에 따라 결과 편차가 발생한다는 한계를 가진다.

### 1.2 문제 정의

본 연구의 목표는 현미경 기반 천적응애 품질 검사를 AI 이미지·영상 분석으로 대체·보조하여, (i) 검사 시간을 단축하고 (ii) 판정 기준을 일관되게 유지하는 것이다. 이를 위해 개체 수·밀도·활력도·증식률을 사육박스 단위로 정량화하고 시간 흐름에 따라 관리하는 로컬 실행형 분석 시스템을 설계·구현하였다.

천적응애의 계수·활력도 측정에는 세 가지 근본적 난점이 존재하며, 본 시스템의 주요 설계 결정은 대부분 이에 대한 대응에서 비롯되었다.

| 난점 | 내용 | 대응 |
|------|------|------|
| 초소형 객체 (0.3mm) | 원본 이미지에서 차지하는 픽셀이 매우 작아 일반 탐지 모델의 다운샘플링 과정에서 특징이 손실됨 | 타일링(tiled inference) 기반 분할 추론 |
| 배경 유사성 | 배지와 응애의 색·질감이 유사하여 오탐·미탐 가능성이 높음 | 촬영 조건 표준화 및 라벨 검수 |
| 시간축 정보의 필요성 | 개체의 생존·활동성은 정지 이미지만으로 판단 불가 | 영상 기반 다중 객체 추적(tracking) |

## 2. 시스템 아키텍처

### 2.1 전체 구성

시스템은 사용자 화면(Frontend) · 서버(Backend) · AI 모델(Model API) · 데이터 저장소(Database)의 4개 서비스로 구성되며, 한 대의 로컬 PC 또는 내부망 서버에서 함께 구동하는 것을 기본 운영 모델로 한다. 인터넷 연결이 제한적인 현장에서도 로컬 추론만으로 동작하도록 설계하였다.

| 구성 요소 | 기술 | 포트 | 책임 |
|-----------|------|------|------|
| Frontend | React 18 + Vite 6 + TypeScript | :80 | 분석 요청·결과 시각화 (Gauge·Heatmap·LineChart 자체 구현) |
| Backend API | Express 5 + Node.js | :3000 | 파일 보관·작업 생성·모델 호출·결과 저장 |
| Model API | FastAPI + YOLO/OpenCV/ONNX | :8000 | 이미지·영상 추론 (탐지·밀도·활력도) |
| Database | PostgreSQL | :5432 | 사육박스·측정·상세 결과 영속 저장 |

AI 분석과 서비스 기능이 느슨하게 결합되어 있어 한 부분을 교체하여도 전체에 미치는 영향이 제한된다. 백엔드는 routes → controllers → services → repositories 계층으로 관심사를 분리하였으며, 모든 라우트 핸들러는 asyncHandler로 감싸 비동기 오류를 일원화된 오류 미들웨어로 전달하고, 다중 테이블 쓰기는 트랜잭션(BEGIN/COMMIT/ROLLBACK)으로 원자성을 보장한다.

### 2.2 요청 처리 모델

이미지 탐지는 **동기 처리**된다. 프론트엔드가 사육박스 식별자와 파일을 multipart로 전송하면, 백엔드가 파일을 저장하고 모델 API를 호출한 뒤 반환된 픽셀 좌표를 이미지 크기로 정규화(0~1 상대 비율)하여 저장·응답한다. 정규화 저장으로 인해 렌더링 시 화면 해상도와 무관하게 동일 위치에 바운딩 박스를 표시할 수 있다.

영상 밀도·활력도 분석은 **비동기 작업(job) + 진행률 폴링** 구조로 처리된다. 업로드 즉시 작업을 생성해 접수 번호를 반환하고 실제 분석은 백그라운드에서 수행하며, 프론트엔드는 진행률 엔드포인트를 반복 폴링하여 샘플별 단계 상태(density → vitality → completed/failed)와 백분율을 표시한다.

### 2.3 데이터 모델

공통 측정 테이블 `measurements`(type = detection/density/vitality)를 허브로 유형별 상세 테이블 — 탐지 박스(`detection_boxes`), 밀도 요약·프레임 단위(`density_results`·`density_frame_counts`), 활력도 요약·시계열(`vitality_results`·`vitality_series`) — 이 외래키로 방사형 연결되며, ON DELETE CASCADE로 정합성을 유지한다. 설계 원칙은 다음과 같다.

- **UUID 기본키** — 분산·병합 환경에서의 식별자 충돌을 방지한다.
- **JSONB 원본 보관** — 분석 결과 원본을 JSONB로 저장하여 스키마 변경 없이 세부 결과를 보존한다.
- **Soft delete** — 사육박스 삭제는 `deleted_at` 기록만 수행하여 측정 이력을 보존하고 휴지통 복구를 지원한다.
- **멱등적 마이그레이션** — `CREATE TABLE IF NOT EXISTS` 기반으로 반복 실행에 안전한 스키마 적용을 보장한다.

## 3. 제안 방법

### 3.1 데이터셋 구축

조명·초점·배율을 표준화하여 수집한 현미경 이미지 약 1만 장에 대해 CVAT로 총 **31,532개의 바운딩 박스**를 라벨링하였다. 클래스는 0 = predator(천적응애), 1 = prey(먹이응애)의 2종이다. 라벨 박스가 객체보다 지나치게 크면 배경이 특징으로 학습되고, 지나치게 작으면 다리·윤곽 정보가 손실되므로, 응애 몸체와 주요 식별 특징이 포함되도록 일정 기준을 적용하고 애매한 객체는 검수를 거쳐 제외·별도 관리하였다. Segmentation 라벨링은 비용 대비 효용을 고려하여 초기 실용 단계에서 제외하였다.

### 3.2 타일링 기반 소형 객체 탐지

탐지 모델은 Ultralytics YOLOv8m을 기반으로 한다. YOLO 계열은 후보 영역 제안과 클래스 판별을 단일 패스로 수행하여 처리 속도 측면에서 유리하다. 그러나 원본 이미지를 통째로 입력하면 다운샘플링 과정에서 0.3mm급 개체의 특징이 소실되므로, 입력을 640×640 타일로 분할하여 추론한다. 타일 경계에 걸친 개체의 미탐을 방지하기 위해 이웃 타일을 중첩시키며(학습 시 25%, 서비스 추론 시 기본 50%), 타일 시작 좌표는 다음과 같이 계산한다.

$$stride = tile\_size \times (1 - overlap)$$

중첩으로 인해 동일 개체가 복수 타일에서 중복 검출되는 문제는, 각 타일의 박스를 원본 좌표계로 역변환한 뒤 동일 클래스 간 IoU를 비교하여 신뢰도가 높은 박스만 남기는 **class-aware NMS**(기본 IoU 임계값 0.3)로 해결한다. 탐지 신뢰도 임계값은 기본 0.5이다.

### 3.3 영상 기반 밀도 추정

밀도 분석은 별도의 예측 모델 없이 장면별 탐지 결과를 통계적으로 집계한다. 10초 미만 영상은 분석에서 제외하고, 기본 10초 분석 구간에서 1초 간격으로 프레임을 샘플링하여 천적응애(predator)만 계수한다.

각 프레임은 선명도(Laplacian variance ≥ 50)와 밝기(40~220)로 품질을 평가하며, 품질 점수는 다음의 가중 합으로 산출한다.

$$Q = 0.65 \times Q_{sharpness} + 0.35 \times Q_{brightness}$$

기준을 통과한 프레임 중 개체 수가 많고 품질 점수가 높은 프레임을 대표 프레임으로 선택하고, 통과 프레임이 없으면 경고를 기록한 뒤 차선책 프레임을 사용한다. 최종 밀도는 전체 샘플 프레임의 평균 개체 수에 1mL 환산 계수(기본 10, 촬영 시야/배지 부피 비율에서 도출)를 곱하여 추정하며, 1mL당 10마리 이상이면 출하 가능(marketable), 미만이면 low 등급을 부여한다.

### 3.4 다중 객체 추적 기반 활력도 산출

활력도는 개체의 이동 속도를 근거로 정량화한다. 영상의 장면마다 개체 중심점을 탐지하고 이를 시간축으로 연결하여 이동 궤적(trajectory)을 생성한다. 동일 개체 판정에는 중심점 거리와 바운딩 박스 중첩(IoU ≥ 0.05)을 함께 사용하며, 연결 후보는 동일 클래스로 한정한다. 유효 이동 임계값은 두 박스의 대각선 길이를 기준으로 최소 8px·최대 60px로 제한하여 이를 초과하는 이동은 오연결로 간주·배제한다. 일시적으로 미검출된 개체는 최대 4장면까지 유지한 뒤 소실 처리하며, 신규 개체는 새로운 추적 대상으로 등록한다.

활력도 계산에는 최소 3장면 이상 관측된 개체만 사용한다. 누적 픽셀 이동 거리를 촬영 배율 환산 계수(기본 1500px/mm, 현미경 스케일 측정값)로 실제 길이(mm)로 변환하고 관측 시간으로 나누어 평균 이동 속도를 구한다. 이 속도를 기준 먹이응애 속도(0.025mm/s) 대비 배율로 환산한 뒤, 로지스틱(S자) 곡선에 통과시켜 0~100점의 활력도 점수를 산출한다. 곡선은 기준 속도 대비 약 3배에서 중간 점수(0.60), 약 6배에서 높은 점수(0.92)가 되도록 두 기준점으로 정의된다.

$$V = w_v \cdot \bar{v} + w_\rho \cdot \rho - w_\sigma \cdot \sigma, \quad w_v + w_\rho + w_\sigma = 1$$

여기서 \\(\bar{v}\\)는 평균 이동 속도, \\(\rho\\)는 활동 개체 비율(active ratio), \\(\sigma\\)는 장시간 정지 개체 비율이다. 활력도 전용 가중치(`model/vitality/best.onnx`)는 밀도 탐지와 독립적으로 입력 해상도(기본 1280)와 설정을 조정할 수 있다.

### 3.5 증식률 산출

증식률은 동일 사육박스의 날짜별 밀도·활력도 기록을 비교한다. 장기 지표는 기간 내 첫 측정과 최신 측정을, 최근 지표는 직전 측정과 최신 측정을 비교하며, 통합 증식률은 다음의 가중 합으로 산출한다 (출하량 결정에 밀도의 기여도가 더 크다는 도메인 판단을 반영).

$$G = 0.75 \times \Delta_{density} + 0.25 \times \Delta_{vitality}$$

최근 밀도 또는 활력도 변화율이 −20% 이하로 급감하면 "주의 관찰"로 표시하며, 그 외에는 통합 증식률 +20% 초과 시 "증식 활발", −10% 미만 시 "감소 추세", 나머지는 "유지 관찰"로 분류한다.

## 4. 실험 및 평가

### 4.1 평가 방법

총 31,532개 바운딩 박스(약 1만 장)를 train/val/test로 분할하고, 성능 수치는 학습에 사용하지 않은 test 셋에서 측정하였다. 계수 오차는 동일 샘플에 대한 수기 계수 값과 AI 계수 값의 비교로 산출하였다.

### 4.2 단계별 성능 개선 (ablation)

| 버전 | 적용 내용 | mAP50 | 기술적 의미 |
|------|-----------|-------|-------------|
| V1 | YOLOv8m 기본 모델 | 0.66 | 원본 이미지 그대로 학습 |
| V2 | 640×640 이미지 분할 | 0.82 | 소형 개체의 특징 손실 감소 |
| V3 | 분할 + 25% overlap | 0.89 | 타일 경계 객체의 미탐 감소 |
| V4 | 분할 + overlap + 중복 정리 | **0.97** | 배경 노이즈 억제 및 특징 강화 |

### 4.3 종합 결과

- **탐지 정확도** — 최종 V4 구성에서 테스트 셋 기준 **mAP50 0.97** 달성
- **분석 시간** — 30개 샘플 기준 수기 계수 약 450분 → AI 분석 약 15분, **약 97% 단축**
- **계수 오차** — 약 1만 마리 기준 오차 약 300마리(**약 3%**) 수준

## 5. 논의: 주요 설계 결정

**ONNX 경량화.** 분석이 실제로 수행되는 환경은 농가·기관의 일반 PC이다. 학습 프레임워크 의존 없이 경량 추론이 가능하도록 PyTorch 가중치(`best.pt`)를 ONNX(`best.onnx`)로 변환하고 로컬 추론 서버로 분리하여, 웹 대시보드와 Electron 데스크톱 앱이 동일한 추론 결과를 공유하는 구조를 취하였다.

**파라미터의 환경변수화.** 밀도·활력도 수치는 촬영 배율과 실제 길이·부피 간 환산 관계에 전적으로 의존한다. 신뢰도 임계값·타일 크기·px/mm 환산 계수·S곡선 기준점 등 20여 개 파라미터를 `CHECKMITE_*` 환경변수로 외부화하여, 현미경·카메라·배율 등 촬영 환경이 변경되어도 **재학습 없이 현장 재보정**이 가능하도록 하였다. 눈금자·표준 스케일 촬영으로 px/mm를 재측정하는 보정 절차를 설치 요건으로 문서화하였다.

**모듈형 구조.** 탐지·추적·분석을 분리하여 신규 학습 데이터 축적 시 가중치 파일 교체만으로 성능을 개선할 수 있으며, 동일 구조를 타 소형 생물 분석으로 확장할 수 있다.

**보안 경계의 명시.** 본 시스템은 내부망·단일 PC 연구용 운영을 전제로 인증·권한 체계를 의도적으로 제외하였다. 보안 경계가 API 계층이 아닌 네트워크 계층에 있음을 기술서에 명시하고, 외부 공개 시 요구되는 보강 사항(루프백 바인딩, 리버스 프록시 + TLS·인증, CORS 허용 출처 제한)을 별도 장으로 규정하였다.

## 6. 한계 및 향후 연구

1. **추적 안정성** — 현행 추적은 단순 IoU·거리 기반으로 개체 겹침·일시 소실에 취약하다. ByteTrack·DeepSORT 등 검증된 추적 알고리즘 도입으로 안정성을 개선할 수 있다.
2. **수평 확장성** — 진행률 작업이 인메모리 Map으로 관리되어 백엔드 재시작 시 진행 중 상태가 유실되며 다중 인스턴스 확장이 불가하다. Redis 등 외부 저장소로의 교체가 요구된다.
3. **회귀 검증 자동화** — 자동화된 단위·통합 테스트가 부재하여 기능 변경 시 회귀 검증을 수동 수행한다. 고정 샘플에 대해 기대 count·density·vitality 범위를 단언하는 회귀 테스트와 CI/CD·컨테이너 도입이 필요하다.
4. **라이선스 제약** — 핵심 탐지 모델(Ultralytics YOLOv8)과 학습 가중치는 AGPL-3.0의 적용을 받으므로, 제품·서비스 형태의 배포 시 전체 소스 공개 또는 상용 라이선스 확보 중 하나를 선택하여야 한다.

## 7. 결론

본 연구는 수작업 현미경 검사에 의존하던 천적응애 품질 평가를 타일링 기반 YOLOv8 탐지와 다중 객체 추적으로 자동화한 시스템을 설계·구현하였다. 타일링·overlap·중복 정리의 단계적 적용으로 테스트 셋 기준 mAP50을 0.66에서 0.97까지 개선하였고, 수기 계수 대비 분석 시간을 약 97% 단축하면서 계수 오차를 약 3% 수준으로 유지하였다. 촬영 환경 변화에 재학습 없이 대응하는 환경변수 기반 보정 체계와 모듈형 구조를 통해, 본 시스템이 타 소형 생물의 정량 분석으로 확장 가능함을 보였다.
