## 1. 서론

### 1.1 연구 배경

천적생물방제(biological control)는 화학 농약 사용을 최소화하면서 해충 개체군을 자연적으로 억제하는 친환경 농업 기술이다. 전북특별자치도농업기술원은 천적생물의 대량 증식·공급 기술을 연구하고 있으며, 천적응애(predatory mite)를 흙과 유사한 배지에서 사육하고 주기적으로 먹이응애(prey mite)를 공급하여 약 2~4주간 증식시킨 뒤 친환경 농가에 공급한다.

공급 품질을 보장하기 위해서는 출하 전 개체 수와 활력도를 정확히 평가하여야 한다. 그러나 기존 검사는 연구원이 현미경으로 개체를 직접 계수하고 활력도를 육안으로 판정하는 수작업에 의존하였다. 이 방식은 샘플 수가 증가할수록 검사 시간이 급증하며, 작업자의 숙련도·피로도·주관적 판단에 따라 결과 편차가 발생한다는 한계를 가진다. 본 연구는 계수·평가 과정을 자동화하여 검사 시간을 단축하고 판정 기준을 일관되게 유지하는 것을 목표로 한다.

### 1.2 문제 정의와 기술적 난점

천적응애의 계수·활력도 측정에는 세 가지 근본적 난점이 존재하며, 시스템의 주요 설계 결정은 대부분 이 난점에 대한 대응에서 비롯되었다.

| 난점 | 내용 | 대응 |
|------|------|------|
| 초소형 객체 (0.3mm) | 원본 이미지에서 차지하는 픽셀이 매우 작아 일반 탐지 모델의 다운샘플링 과정에서 특징이 손실됨 | 타일링(tiled inference) 기반 분할 추론 |
| 배경 유사성 | 배지와 응애의 색·질감이 유사하여 오탐·미탐 가능성이 높음 | 조명·초점·배율 표준화 수집 및 라벨 검수 |
| 시간축 정보의 필요성 | 개체의 생존·활동성은 정지 이미지만으로 판단 불가 | 영상 기반 다중 객체 추적(tracking) 분석 |

이 세 문제를 하나의 분석 과정으로 통합하여 해결한다. AI 객체 탐지로 응애의 위치·종류를 식별하고, 이미지를 작은 조각으로 분할하여 소형 개체의 특징 손실을 방지하며, 중복 검출된 개체는 후처리로 정리한다. 영상에 대해서는 다수의 장면에서 개체를 추적하고 이동 속도를 근거로 활력도를 산출한다.

### 1.3 기능 요구사항과 기술적 대응

기능 요구사항은 입력 → 분석 → 저장 → 시각화의 흐름으로 구성된다. 이미지·영상을 업로드하면 천적응애/먹이응애를 분류·계수하고, 영상은 개체별 이동 경로를 추적하여 활력도를 산출하며, 날짜·샘플·결과를 데이터베이스에 누적하여 대시보드로 추세를 확인한다.

| 구분 | 요구사항 | 기술적 대응 |
|------|----------|-------------|
| 정확도 | 수기 계수 대비 오차 최소화 | AI 객체 탐지 + 이미지 분할 + 겹침 보정 + 중복 정리 + 개체 추적 |
| 속도 | 현장 사용 가능한 처리 시간 | 단일 패스 탐지(YOLO) + 타일 처리 + 분석 구간 제한(기본 10초) |
| 재현성 | 검사자 편차 감소 | AI 자동 계수와 동일한 판정 기준(신뢰도·NMS·환산 계수) 적용 |
| 확장성 | 타 소형 생물 분석 가능 | 탐지·추적·분석이 분리된 모듈형 구조, 파라미터의 환경변수화 |
| 운영성 | 인터넷 불안정 환경 대응 | 로컬 PC 기반 추론 구조, 외부 의존 없는 로컬 저장 |

## 2. 시스템 아키텍처

### 2.1 계층 구성과 책임

시스템은 사용자 화면(Frontend) · 서버(Backend) · AI 모델(Model API) · 데이터 저장소(Database)의 4개 서비스로 구성되며, 한 대의 로컬 PC 또는 내부망 서버에서 함께 구동하는 것을 기본 운영 모델로 한다. AI 분석과 서비스 기능이 느슨하게 결합되어 있어 한 부분을 교체하여도 전체에 미치는 영향이 제한된다.

| 구성 요소 | 기술 | 책임 |
|-----------|------|------|
| Frontend | React 18 + Vite 6 + TypeScript | 분석 요청과 결과 표시. 라우팅 라이브러리 없이 탭 상태와 localStorage로 화면을 전환하며 Gauge·Heatmap·LineChart 등 시각화 컴포넌트를 자체 구현 |
| Backend API | Express 5 + Node.js | 업로드 파일 보관, 분석 작업 생성, AI 모델 호출, 결과 저장 |
| Model API | FastAPI + YOLO/OpenCV/ONNX | 사진·영상 장면에서 응애를 탐지하고 장면별 결과를 결합하여 밀도·활력도 지표로 변환 |
| Database | PostgreSQL | 사육박스·업로드 파일·분석 작업·측정 결과·개체 위치 상세 결과를 구분 저장 |

백엔드는 routes → controllers → services → repositories 계층으로 관심사를 분리한다. routes는 HTTP 메서드·경로와 미들웨어 연결, controllers는 요청 파싱·검증·서비스 위임·응답 생성, services는 도메인 로직·모델 호출·트랜잭션 조합, repositories는 SQL 실행과 행↔객체 매핑을 담당한다. 모든 라우트 핸들러는 asyncHandler로 감싸 비동기 오류를 일원화된 오류 미들웨어로 전달하고, 도메인 오류는 상태 코드를 가진 HttpError로 던지며, 다중 테이블 쓰기는 트랜잭션(BEGIN/COMMIT/ROLLBACK)으로 원자성을 보장한다. 데이터베이스의 snake_case 컬럼과 애플리케이션의 camelCase 필드는 전용 매퍼 계층에서 변환하여 계약을 분리한다.

### 2.2 요청 처리 모델

**이미지 탐지(동기).** ① 프론트엔드가 사육박스 식별자(boxId)와 파일을 multipart로 전송하면, ② 백엔드가 파일을 저장하고 모델 API의 이미지 추론 엔드포인트를 호출한 뒤, ③ 반환된 픽셀 좌표를 이미지 크기로 나누어 0~1 상대 비율의 바운딩 박스로 정규화하고, ④ 측정·탐지 박스 테이블에 저장한 결과를 응답한다. 정규화 저장으로 인해 렌더링 시 화면 해상도와 무관하게 동일 위치에 박스를 표시할 수 있다.

**영상 밀도·활력도 분석(비동기).** ① 프론트엔드가 복수의 1mL 배지 영상을 업로드하면, ② 백엔드는 즉시 진행률 작업(job)을 생성하여 접수 번호를 반환하고 실제 분석을 백그라운드에서 시작한다. ③ 각 샘플에 대해 모델 API의 밀도 분석과 활력도 분석을 순차 호출하고, ④ 첫 번째 샘플에 대해서는 추적 결과를 시각화한 tracking overlay 영상을 생성하며, ⑤ 프론트엔드는 진행률 엔드포인트를 반복 폴링하여 단계별 상태와 최종 결과를 표시한다.

진행률 작업의 상태는 queued → processing → completed/failed로 전이하며, 샘플별로 density(밀도 분석 중)·vitality(활력도 분석 중)·completed·failed의 세부 상태와 백분율을 갱신한다. 진행률은 인메모리 자료구조로 관리되므로 완료된 측정 결과만 데이터베이스에 영속되며, 이는 단일 인스턴스 운영을 전제한 의도적 트레이드오프이다(6장).

### 2.3 데이터 모델

공통 측정 테이블 `measurements`(type = detection/density/vitality)를 허브로 유형별 상세 테이블이 외래키로 방사형 연결되며, ON DELETE CASCADE로 정합성을 유지한다.

| 테이블 | 역할 | 핵심 속성 |
|--------|------|-----------|
| culture_boxes | 사육박스 기본 정보 | name, started_at, deleted_at |
| uploaded_files | 업로드 파일 메타데이터 | mime_type, storage_path, checksum |
| analysis_jobs | 분석 작업 상태 | type, status, completed_at |
| measurements | 공통 측정 이력 (허브) | count_value, density_per_liter, vitality_score |
| density_results / density_frame_counts | 밀도 분석 요약 / 프레임 단위 count·품질 | estimated_count_per_ml, density_grade, frame_index, quality |
| vitality_results / vitality_series | 활력도 요약 / 프레임별 시계열 | vitality_score, active_ratio, average_speed_mm_per_sec |
| detection_boxes | 탐지 bounding box | class_name, confidence, x/y/width/height (0~1 정규화) |
| growth_snapshots | 증식률 스냅샷 | density_change_rate_percent, result_json |
| trash_events | 삭제/복구 이벤트 로그 | entity_type, action, payload |

설계 원칙은 네 가지이다. (i) **UUID 기본키** — 분산·병합 환경에서의 식별자 충돌을 방지한다. (ii) **JSONB 원본 보관** — 분석 결과 원본(result_summary·quality·payload 등)을 JSONB로 저장하여 스키마 변경 없이 세부 결과를 보존한다. (iii) **Soft delete** — 사육박스 삭제는 deleted_at 기록만 수행하여 측정 이력을 보존하고 휴지통 복구를 지원하며, trash_events로 삭제/복구 이력을 추적한다. (iv) **멱등적 마이그레이션** — IF NOT EXISTS 기반 구문으로 반복 실행에 안전한 스키마 적용을 보장하고, 스키마 파일 자체를 단일 진실 원본(single source of truth)으로 유지한다.

## 3. 객체 탐지 방법론

### 3.1 데이터셋 구축과 라벨링 기준

조명·초점·배율을 표준화하여 수집한 현미경 기반 이미지 약 1만 장에 대해 CVAT로 총 **31,532개의 바운딩 박스**를 라벨링하였다. 클래스는 0 = predator(천적응애), 1 = prey(먹이응애)의 2종이다.

라벨링 품질은 탐지 성능의 상한을 결정한다. 라벨 박스가 객체보다 지나치게 크면 배경이 특징으로 학습되고, 지나치게 작으면 다리·윤곽 등 식별 정보가 손실된다. 따라서 응애 몸체와 주요 식별 특징이 포함되도록 일정 기준을 적용하고, 판별이 애매한 객체는 검수를 거쳐 제외·별도 관리하였다. Segmentation 라벨링은 비용 대비 효용을 고려하여 초기 실용 단계에서 제외하고 bounding box 방식을 채택하였다.

### 3.2 YOLOv8 탐지 파이프라인

탐지 모델은 Ultralytics YOLOv8m을 기반으로 한다. 입력(640×640 타일)은 ① CSP 기반 **Backbone**에서 다단계 특징 맵(P1~P5, 1/2~1/32 스케일)으로 추출되고, ② **Neck**(FPN + PAN)에서 다중 스케일 특징이 상향·하향 경로로 융합되며, ③ **Detection Head**에서 바운딩 박스 좌표(x, y, w, h)·객체성 점수(objectness)·클래스 확률(predator/prey)을 동시에 예측한다. 최종 출력은 각 개체의 바운딩 박스·클래스·신뢰도(confidence)이며, 후처리로 NMS를 적용한다.

YOLO 계열은 후보 영역 제안과 클래스 판별을 단일 패스로 수행하는 one-stage 구조로서 처리 속도 측면에서 유리하여, "현장 사용 가능한 처리 시간"이라는 요구사항(1.3)에 부합한다. 탐지 신뢰도 임계값은 기본 0.5를 사용한다.

### 3.3 타일링 기반 분할 추론

원본 이미지를 통째로 입력하면 네트워크 입력 해상도로의 축소 과정에서 0.3mm급 개체의 특징이 소실된다. 이를 방지하기 위해 입력을 640×640 타일로 분할하여 개별 추론한다(SAHI-style tiled inference). 타일 경계에 걸친 개체의 미탐을 방지하기 위해 이웃 타일을 중첩시키며, 학습 시에는 25%, 서비스 추론 시에는 기본 50%의 겹침을 적용한다. 타일 시작 좌표는 다음과 같이 계산하고, 마지막 타일은 이미지 끝에 맞추어 보정한다.

$$stride = tile\_size \times (1 - overlap)$$

### 3.4 Class-aware NMS 기반 중복 정리

중첩 타일링으로 인해 동일 개체가 복수 타일에서 중복 검출된다. 각 타일의 박스를 원본 좌표계로 역변환한 뒤, **동일 클래스 간에만** IoU를 비교하여 신뢰도가 높은 박스를 남기고 나머지를 억제한다(class-aware NMS, 기본 IoU 임계값 0.3). 클래스를 구분하여 억제함으로써 천적응애와 먹이응애가 인접한 경우 서로 다른 클래스의 검출이 소거되는 문제를 방지한다. 최종 응답에는 이미지 크기, 처리한 타일 수, 클래스별 마릿수, 전체 개체 수, 개체별 위치가 포함된다.

## 4. 영상 기반 밀도 추정

### 4.1 프레임 샘플링

밀도 분석은 별도의 예측 모델 없이 장면별 탐지 결과를 통계적으로 집계한다. 10초 미만의 영상은 분석 신뢰성이 낮아 제외하며, 기본 10초의 분석 구간에서 `sample_stride = fps × 1초` 간격으로 프레임을 샘플링하여 천적응애(predator)만 계수한다.

### 4.2 프레임 품질 평가와 대표 프레임 선택

각 프레임은 선명도와 밝기로 품질을 평가한다. 선명도는 Laplacian variance로 측정하여 기준값 50 이상, 밝기는 40~220 범위를 통과 기준으로 하며, 품질 점수는 다음의 가중 합으로 산출한다.

$$Q = 0.65 \times Q_{sharpness} + 0.35 \times Q_{brightness}$$

기준을 통과한 프레임 중 개체 수가 많고 품질 점수가 높은 프레임을 대표 프레임으로 선택하고, 통과 프레임이 없는 경우 경고를 기록한 뒤 가장 나은 프레임을 차선으로 사용한다. 이 품질 게이트는 초점 이탈·조명 불량 프레임이 밀도 추정을 오염시키는 것을 방지한다.

### 4.3 부피 환산과 등급 판정

최종 밀도는 전체 샘플 프레임의 평균 개체 수에 1mL 환산 계수(기본 10)를 곱하여 추정한다. 이 계수는 촬영 시야가 1mL 배지에서 차지하는 비율로부터 도출된 경험적 보정값이다. 1L 단위 값은 여기에 ×1000을 적용한다. 출하 품질 기준으로 1mL당 10마리 이상이면 marketable, 미만이면 low 등급을 부여한다.

## 5. 다중 객체 추적 기반 활력도 산출

### 5.1 궤적 생성과 개체 연결

영상의 장면마다 개체 중심점을 탐지하고 이를 시간축으로 연결하여 이동 궤적(trajectory)을 생성한다. 동일 개체 판정에는 **중심점 거리와 바운딩 박스 중첩(IoU ≥ 0.05)** 을 함께 사용하며, 연결 후보는 동일 클래스로 한정한다. 유효 이동 임계값은 두 박스의 대각선 길이를 기준으로 동적으로 계산하되 최소 8px·최대 60px로 제한하여, 이를 초과하는 이동은 오연결(identity switch)로 간주·배제한다. 일시적으로 미검출된 개체는 최대 4장면(MAX_TRACK_MISSES)까지 유지한 뒤 소실 처리하며, 신규 개체는 새로운 추적 대상으로 등록한다.

### 5.2 속도 환산과 로지스틱 점수화

활력도 계산에는 최소 3장면 이상 관측된 개체만 사용하여 순간 노이즈에 의한 왜곡을 억제한다. 누적 픽셀 이동 거리를 촬영 배율 환산 계수(기본 1500px/mm, 현미경 스케일 측정값)로 실제 길이(mm)로 변환하고 관측 시간으로 나누어 개체별 평균 이동 속도를 구한다.

평균 속도는 기준 먹이응애 속도(0.025mm/s) 대비 배율로 정규화한 뒤, 완만한 로지스틱(S자) 곡선에 통과시켜 0~100점의 활력도 점수로 변환한다. 곡선은 기준 속도 대비 약 3배에서 중간 점수(0.60), 약 6배에서 높은 점수(0.92)가 되도록 두 기준점으로 정의된다. 선형 환산 대신 로지스틱 곡선을 채택함으로써 극단적 고속 이동이 점수를 비정상적으로 지배하는 것을 방지하고, 정상 활동 범위 내에서의 변별력을 확보한다.

종합 활력도 지수는 평균 이동 속도, 활동 개체 비율, 장시간 정지 개체 비율의 가중 결합으로 정의된다.

$$V = w_v \cdot \bar{v} + w_\rho \cdot \rho - w_\sigma \cdot \sigma, \quad w_v + w_\rho + w_\sigma = 1$$

여기서 \\(\bar{v}\\)는 평균 이동 속도, \\(\rho = N_a / N\\)는 활동 개체 비율(active ratio), \\(\sigma = N_s / N\\)는 장시간 정지 개체 비율이다. active_ratio는 "확정 트랙 중 총 픽셀 이동 거리가 이동 임계(기본 2px)의 2배인 4px 이상인 트랙의 비율"로 산출되며, vitality_score는 평균 속도 기반 로지스틱 점수 × 100이다. 두 값은 서로 다른 지표이므로 함께 해석하여야 한다 — 전자는 "움직이는 개체가 얼마나 많은가", 후자는 "움직이는 속도가 얼마나 빠른가"를 나타낸다.

활력도 탐지는 전용 가중치(`model/vitality/best.onnx`)를 사용하여 밀도 탐지와 독립적으로 입력 해상도(기본 1280)와 설정을 조정할 수 있다.

## 6. 증식률 산출

증식률은 동일 사육박스의 날짜별 밀도·활력도 기록을 비교한다. **장기 지표**는 기간 내 첫 측정과 최신 측정을, **최근 지표**는 직전 측정과 최신 측정을 비교한다. 통합 증식률은 다음의 가중 합으로 산출하며, 가중치 0.75/0.25는 출하량 결정에 밀도의 기여도가 더 크다는 도메인 판단을 반영한 것이다.

$$G = 0.75 \times \Delta_{density} + 0.25 \times \Delta_{vitality}$$

판정 규칙은 다음과 같다. 최근 밀도 또는 활력도 변화율이 −20% 이하로 급감하면 "주의 관찰"로 우선 표시하며, 그 외에는 통합 증식률이 +20% 초과이면 "증식 활발", −10% 미만이면 "감소 추세", 나머지는 "유지 관찰"로 분류한다. 급감 조건을 우선 평가하는 것은 통합 지표가 가중 평균의 특성상 단일 지표의 급락을 은폐할 수 있기 때문이다.

## 7. 촬영 환경과 캘리브레이션 이론

시스템의 밀도·활력도 수치는 촬영 배율과 실제 길이·부피 간 환산 관계에 전적으로 의존한다. 환산 계수는 특정 촬영 환경을 기준으로 보정된 값이므로, 다른 현미경·카메라·배율로 촬영하면 결과가 체계적으로(systematically) 틀어진다. 따라서 촬영 환경과 캘리브레이션 전제를 필수 설치 요건으로 규정하였다.

| 계수 | 기본값 | 근거·의미 |
|------|--------|-----------|
| 1mL 환산 계수 | 10 | 프레임(샘플 시야) 평균 개체 수 → 1mL 환산. 촬영 시야/배지 부피 비율에서 도출 |
| marketable 임계 | 1mL당 10마리 | 출하 품질 기준. 이상 marketable, 미만 low |
| 증식률 가중치 | 밀도 0.75 / 활력도 0.25 | 출하량 결정에 밀도 기여도가 더 크다는 도메인 판단 |
| px/mm 환산 | 1500 | 촬영 배율 기반 px→mm 환산 (현미경 스케일 측정값) |

보정 절차는 재학습 없이 파라미터 조정만으로 수행된다. (i) **px/mm 보정** — 눈금자·표준 스케일을 촬영하여 1mm가 몇 px에 해당하는지 측정한 뒤 환산 계수를 갱신한다. (ii) **1mL 환산 보정** — 촬영 시야가 1mL 배지에서 차지하는 비율이 달라지면 환산 계수를 재산정한다. (iii) **기준 속도 재조정** — 활력도 S곡선은 기준 먹이응애 속도 대비 배율로 정의되므로, 대상 종이나 사육 환경이 바뀌면 기준 속도와 곡선 기준점을 재정의한다. 추론 시에도 학습 데이터와 동일한 현미경 배율·작업 거리를 유지하여야 타일링(640px)·px/mm 환산이 유효하며, 밀도 프레임 품질 기준을 충족하도록 균일한 밝기·반사 없는 조명이 요구된다. 보정 이력을 함께 기록하면 과거 데이터와의 비교 가능성이 확보된다.

## 8. 실험 및 평가

### 8.1 평가 방법론

총 31,532개 바운딩 박스(약 1만 장)를 train/val/test로 분할하고, 성능 수치는 학습에 사용하지 않은 test 셋에서 측정하였다. 계수 오차는 동일 샘플에 대한 수기 계수 값과 AI 계수 값의 비교로 산출하며, 재현성을 위해 측정 샘플 수·촬영 조건·신뢰도 임계값을 함께 명시하는 것을 원칙으로 한다. mAP50 외에 mAP50-95, 클래스별 precision·recall, 혼동 행렬(predator↔prey 오분류)을 함께 기록하면 소형 객체·배경 유사성 난점에 대한 성능을 구체화할 수 있다.

### 8.2 단계별 성능 개선 (Ablation Study)

| 버전 | 적용 내용 | mAP50 | 기술적 의미 |
|------|-----------|-------|-------------|
| V1 | YOLOv8m 기본 모델 | 0.66 | 원본 이미지 그대로 학습 |
| V2 | 640×640 이미지 분할 | 0.82 | 소형 개체의 특징 손실 감소 |
| V3 | 분할 + 25% overlap | 0.89 | 타일 경계 객체의 미탐 감소 |
| V4 | 분할 + overlap + 중복 정리 | **0.97** | 배경 노이즈 억제 및 특징 강화 |

타일링 단독으로 +0.16, 경계 중첩으로 +0.07, 중복 정리로 +0.08의 단계적 개선을 보였으며, 이는 1.2절의 난점 분석 — 소형 객체의 특징 손실이 성능 저하의 지배적 요인이라는 가설 — 과 부합한다.

### 8.3 종합 결과

- **탐지 정확도** — 최종 V4 구성에서 테스트 셋 기준 **mAP50 0.97** 달성
- **분석 시간** — 30개 샘플 기준 수기 계수 약 450분 → AI 분석 약 15분. 시간 단축률은 다음과 같다.

$$1 - \frac{t_{AI}}{t_{manual}} = 1 - \frac{15}{450} \approx 97\%$$

- **계수 오차** — 약 1만 마리 기준 오차 약 300마리(**약 3%**) 수준

## 9. 논의: 주요 설계 결정

**ONNX 경량화.** 분석이 실제로 수행되는 환경은 농가·기관의 일반 PC이다. 학습 프레임워크 의존 없이 경량 추론이 가능하도록 PyTorch 가중치(`best.pt`)를 ONNX(`best.onnx`)로 변환하고 로컬 추론 서버로 분리하여, 웹 대시보드와 Electron 데스크톱 앱이 동일한 추론 결과를 공유하는 구조를 취하였다.

**파라미터의 환경변수화.** 신뢰도 임계값·타일 크기·NMS IoU·프레임 품질 기준·px/mm 환산·S곡선 기준점 등 20여 개 파라미터를 환경변수로 외부화하여, 촬영 환경이 변경되어도 재학습 없이 현장 재보정이 가능하도록 하였다(7장). 이는 "확장성: 타 소형 생물 분석 가능"(1.3) 요구사항의 실현 수단이기도 하다.

**모듈형 구조.** 탐지·추적·분석을 분리하여 신규 학습 데이터 축적 시 가중치 파일 교체만으로 성능을 개선할 수 있으며, 동일 구조를 타 소형 생물 분석으로 확장할 수 있다.

**데이터 보존 우선 설계.** 연구 데이터의 특성상 측정 이력의 손실은 치명적이므로, soft delete·JSONB 원본 보관·업로드 파일 체크섬으로 데이터 보존을 우선하였다. 과거 회차 상세 화면은 저장 부담이 큰 tracking overlay 영상을 재생하지 않고 저장된 수치 결과만 재표시하여 보관 비용과 재현성을 균형시켰다.

**보안 경계의 명시.** 본 시스템은 내부망·단일 PC 연구용 운영을 전제로 인증·권한 체계를 의도적으로 제외하였다. 보안 경계가 API 계층이 아닌 네트워크 계층에 있음을 기술서에 명시하고, 외부 공개 시 요구되는 보강 사항을 별도로 규정하였다.

모델 API는 파라미터 변경에 따라 결과가 민감하게 변하므로, 대표 이미지·영상 고정 샘플에 대한 회귀 테스트는 파라미터 튜닝 시의 안전망으로 특히 중요하다.

## 11. 결론

본 연구는 수작업 현미경 검사에 의존하던 천적응애 품질 평가를 타일링 기반 YOLOv8 탐지와 다중 객체 추적으로 자동화한 시스템을 설계·구현하였다. 31,532개 바운딩 박스의 표준화 데이터셋을 구축하고, 타일링·overlap·class-aware NMS의 단계적 적용으로 테스트 셋 기준 mAP50을 0.66에서 0.97까지 개선하였으며, 수기 계수 대비 분석 시간을 약 97% 단축하면서 계수 오차를 약 3% 수준으로 유지하였다. 프레임 품질 게이트 기반 밀도 추정, 로지스틱 점수화 기반 활력도 산출, 가중 결합 기반 증식률 판정을 하나의 파이프라인으로 통합하고, 환산 계수의 환경변수화로 재학습 없는 현장 캘리브레이션 체계를 확립하였다. 본 시스템의 모듈형 구조는 타 소형 생물의 정량 분석으로의 확장 가능성을 제공한다.
