## 배경 — 왜 만들었나

천적생물방제는 화학 농약을 최소화하면서 해충을 억제하는 친환경 농업 기술이다. 전북특별자치도농업기술원은 천적응애를 배지에서 약 2~4주간 증식시켜 친환경 농가에 공급하는데, **출하 품질을 보장하려면 개체 수와 활력도를 정확히 평가**해야 한다.

기존에는 연구원이 현미경으로 직접 계수하고 활력도를 육안으로 판정했다. 이 방식은 샘플이 늘수록 검사 시간이 급증하고, 작업자의 숙련도·피로도에 따라 결과 편차가 발생한다. CheckMite는 이 계수·평가 과정을 자동화해 **검사 시간을 줄이고 판정 기준을 일관되게 유지**하는 것을 목표로 했다.

## 기술적 난점 3가지와 대응

| 난점 | 내용 | 대응 |
|------|------|------|
| 초소형 객체 (0.3mm) | 원본 이미지에서 차지하는 픽셀이 매우 작아 일반 탐지 모델에서 특징이 손실됨 | **타일링(이미지 분할) 추론** |
| 배경 유사성 | 배지와 응애의 색·질감이 유사해 오인·누락 가능성이 높음 | **학습 데이터 표준화·검수** |
| 시간축 필요 | 개체의 생존·활동성은 정지 이미지로 판단 불가 | **영상 기반 tracking 분석** |

## 시스템 구성

프론트엔드 · 백엔드 · 모델 API · 데이터베이스 네 개 서비스가 한 대의 PC 또는 내부망 서버에서 함께 동작하는 **로컬 실행형** 구조다. 인터넷이 제한된 현장에서도 로컬 추론만으로 동작한다.

| 구성 요소 | 기술 | 역할 |
|-----------|------|------|
| Frontend | React 18 + Vite + TS | 분석 요청·결과 대시보드 (Gauge·Heatmap·LineChart 자체 구현) |
| Backend API | Express 5 + Node.js | 파일 보관·작업 생성·모델 호출·결과 저장 |
| Model API | FastAPI + YOLO/OpenCV/ONNX | 이미지·영상 추론 (탐지·밀도·활력도) |
| Database | PostgreSQL | 사육박스·측정·상세 결과 영속 저장 |

이미지 탐지는 동기 처리하고, 영상 밀도·활력도 분석은 **비동기 작업(job) + 진행률 폴링** 구조로 처리한다. 백엔드는 routes → controllers → services → repositories 계층으로 관심사를 분리했고, 측정 결과는 `measurements` 테이블을 허브로 유형별 상세 테이블(탐지 박스·밀도 프레임·활력도 시계열)이 연결된다. 사육박스 삭제는 soft delete로 측정 이력을 보존한다.

## AI 파이프라인

### 데이터셋

- 조명·초점·배율을 표준화해 수집한 **현미경 이미지 약 1만 장**
- CVAT로 라벨링한 **바운딩 박스 총 31,532개**, 클래스 2종 (predator=천적응애 / prey=먹이응애)
- 라벨 박스가 너무 크면 배경을 특징으로 학습하고 너무 작으면 다리·윤곽 정보가 손실되므로, 일정 기준을 적용하고 애매한 객체는 검수로 제외

### 타일링 기반 소형 객체 탐지

원본 이미지를 통째로 넣으면 축소 과정에서 0.3mm 개체의 특징이 사라진다. 이를 막기 위해 **640×640 타일로 분할**하고 경계에 걸친 개체를 놓치지 않도록 이웃 타일을 겹친다(추론 시 기본 50% overlap). 겹침으로 같은 개체가 여러 타일에서 중복 검출되면, 박스를 원본 좌표로 되돌린 뒤 같은 클래스끼리 IoU를 비교해 신뢰도가 높은 박스만 남긴다(**class-aware NMS**, IoU 0.3).

### 영상 밀도 분석

10초 분석 구간에서 1초 간격으로 프레임을 샘플링해 천적응애만 계수한다. 각 프레임은 **선명도(Laplacian variance ≥ 50)와 밝기(40~220)로 품질을 평가**해 대표 프레임을 선택하고, 전체 샘플 프레임의 평균 개체 수에 1mL 환산 계수를 곱해 밀도를 추정한다. 1mL당 10마리 이상이면 출하 가능(marketable) 등급을 부여한다.

### Tracking 기반 활력도 분석

프레임마다 개체 중심점을 찾아 이동 경로를 만든다. 같은 개체 판단에는 **중심점 거리 + 바운딩 박스 IoU(≥0.05)** 를 쓰고, 박스 대각선 기준 유효 이동 임계값(최소 8px·최대 60px)을 넘는 이동은 오연결로 제외한다. 3장면 이상 관측된 개체의 누적 이동 거리를 촬영 배율 환산값(1500px/mm)으로 실제 속도(mm/s)로 바꾸고, 기준 먹이응애 속도(0.025mm/s) 대비 배율을 **로지스틱(S자) 곡선**에 통과시켜 0~100점 활력도를 산출한다.

### 증식률 산출

동일 사육박스의 날짜별 기록을 비교해 **통합 증식률 = 밀도 변화율 × 0.75 + 활력도 변화율 × 0.25**로 가중 합산하고, 변화 추세에 따라 "증식 활발 / 유지 관찰 / 감소 추세 / 주의 관찰"로 라벨링한다.

## 성능 검증

| 버전 | 적용 내용 | mAP50 |
|------|-----------|-------|
| V1 | YOLOv8m 기본 모델 | 0.66 |
| V2 | 640×640 이미지 분할 | 0.82 |
| V3 | 분할 + 25% overlap | 0.89 |
| V4 | 분할 + overlap + 중복 정리 | **0.97** |

- **분석 시간 97% 단축** — 30개 샘플 기준 수기 계수 약 450분 → AI 분석 약 15분
- **계수 오차 약 3%** — 약 1만 마리 기준 오차 약 300마리 수준
- 성능 수치는 학습에 사용하지 않은 test 셋에서 측정 (train/val/test 분리)

## 내가 한 일 (3인 팀에서의 역할)

팀 공동으로 요구사항 분석과 시스템 설계를 진행했고, 그 위에서 내가 담당한 작업은 다음과 같다.

- **YOLO 객체 탐지 모델 학습·경량화** — 소형 개체 탐지 모델을 학습하고 `best.pt`를 `best.onnx`로 변환, 로컬 추론 서버로 분리 운영
- 사육박스별 **밀도·활력도·증식률 분석 파이프라인**을 웹앱으로 통합 — React 대시보드 + Express API + PostgreSQL
- **Electron 데스크톱 앱(V1)** 패키징·배포와 사용자·설치 매뉴얼, **시스템 기술서**·발표자료 작성 (농업기술원 신청 최종본)

## 핵심 설계 결정

- **ONNX 변환** — 분석이 쓰이는 곳은 농가·기관의 일반 PC라, 무거운 학습 프레임워크 의존 없이 가볍게 추론하도록 `best.pt → best.onnx`로 경량화했다.
- **파라미터의 환경변수화** — 신뢰도 임계값·타일 크기·px/mm 환산·S곡선 기준점 등 20여 개 파라미터를 `CHECKMITE_*` 환경변수로 분리해, 촬영 환경(배율·조명)이 바뀌어도 **재학습 없이 현장에서 보정**할 수 있게 했다.
- **모듈형 구조** — 탐지·추적·분석을 분리해 `best.pt` 교체만으로 성능을 개선하거나 타 소형 생물 분석으로 확장할 수 있다.

## 한계와 향후 과제

- 추적이 단순 IoU·거리 기반이라 개체 겹침·일시 소실에 취약하다 → **ByteTrack·DeepSORT** 도입으로 안정화 여지
- 진행률 작업이 인메모리 Map이라 다중 인스턴스 확장이 안 된다 → Redis 등 외부 저장소로 교체
- 자동화된 단위·통합 테스트가 없어 회귀 검증이 수동이다 → 고정 샘플 기준 회귀 테스트·CI/CD·컨테이너 도입
- 핵심 탐지 모델(Ultralytics YOLOv8)이 **AGPL-3.0**이라, 제품·서비스 형태 배포 시 소스 공개 또는 상용 라이선스 검토가 필요하다
