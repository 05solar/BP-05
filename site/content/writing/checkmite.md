## 활동 개요

- **시기**: 2026년 1학기 (4학년 1학기 산학실전캡스톤) — **완료**
- **팀 구성**: 3인 팀, 농업기술원 연계 산학 프로젝트
- **결과**: 🏆 **2026 SW 산학실전캡스톤 대상 (SW사업단장상, 전북대학교 SW중심사업단)**
- **기술**: YOLO (best.pt → best.onnx) · React + Vite + TypeScript · Express + Node.js · PostgreSQL · Electron

## 왜 만들었나 (문제와 목표)

해충 방제에 쓰이는 천적 곤충 **응애**는 사육박스에서 증식시켜 공급하는데, 증식이 잘 되고 있는지(개체 수·활력도·증식률)를 **사람이 눈으로 관찰해 판정**하고 있었다. 이 방식은 시간이 오래 걸리고 관찰자마다 판정 편차가 크다는 문제가 있었고, 농업기술원의 현장 수요에서 과제가 출발했다.

목표는 사육박스 이미지/영상을 넣으면 **객체 탐지 → 밀도 측정 → 활력도 측정 → 증식률 분석**까지 자동으로 산출해, 눈으로 하던 모니터링을 정량화하는 것이었다.

## 내가 한 일 (3인 팀에서의 역할)

팀 공동으로 요구사항 분석과 시스템 설계를 진행했고, 그 위에서 내가 담당한 작업은 다음과 같다.

- **YOLO 객체 탐지 모델 학습·경량화** — 소형 개체(응애) 탐지 모델을 학습하고 `best.pt`를 `best.onnx`로 변환, **로컬 추론 서버**로 분리 운영
- 사육박스별 **밀도·활력도·증식률 분석 파이프라인**을 웹앱으로 통합 — React 대시보드 + Express API + PostgreSQL
- **Electron 데스크톱 앱(V1)** 패키징·배포와 사용자·설치 매뉴얼, 기술서·발표자료 작성 (농업기술원 신청 최종본)

## 어떻게 만들었나 (과정과 선택 이유)

진행 단계는 **데이터 준비·모델 학습 → 모델 경량화(ONNX 변환) → 추론 서버 분리 → 웹앱 통합 → 데스크톱 앱(V1) 배포** 순이었다.

이 중 **PyTorch 모델(best.pt)을 ONNX(best.onnx)로 변환**한 것이 핵심 선택이었다. 분석이 실제로 쓰이는 곳은 농가·기관의 일반 PC 환경이라, 무거운 학습 프레임워크 의존 없이 가볍게 추론할 수 있어야 했기 때문이다. 변환한 모델을 로컬 추론 서버로 분리해 두어, 웹 대시보드와 Electron 앱이 같은 추론 결과를 쓰는 구조로 만들었다.

## 산출물

- **분석 웹앱** — 사육박스별 탐지 결과와 밀도·활력도·증식률을 보여주는 React 대시보드 (위 대표 이미지가 실제 화면)
- **YOLO 탐지 모델** — `best.pt` / 경량화된 `best.onnx`

- **기술서·발표자료** — 증식률·활력도 분석 시스템 기술서 (농업기술원 신청 최종본)
- 코드: [GitHub — checkmiteV1](https://github.com/05solar/checkmiteV1)

## 배운 점과 다음 개선 방향

**배운 점**: 모델 하나를 만드는 것과 그걸 **서비스로 묶는 것은 전혀 다른 일**이라는 걸 체감했다. 학습 → 경량화 → 서빙 → UI → 배포까지 전 과정을 겪으면서, 특히 "모델이 돌아가는 환경(현장 PC)"을 기준으로 기술을 선택하는 관점을 얻었다.

**한계와 개선 방향**: 개발 당시 탐지 정확도(mAP)나 수작업 대비 시간 단축 같은 **정량 지표를 체계적으로 기록하지 못한 것**이 아쉽다. 다음 단계로는 평가 데이터셋과 지표 기록을 정리해 모델 버전별 성능 리포트를 자동화하고, 이를 근거로 탐지 정확도를 개선하는 것이 목표다.
