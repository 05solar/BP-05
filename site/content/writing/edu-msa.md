**수행 정보** — 2026년 진행 중 · **단독 개발**(풀스택 + 인프라) · 내부망 전제 사내 포털

## 문제

교육청 구성원이 단기 교육에서 만든 프로그램은 대부분 개인 PC에만 남아 재사용되지 못한다. 내부망 환경이라 소스를 외부로 반출할 수 없고, 비개발 직원이 만든 프로그램을 운영 서비스로 띄워 줄 전담 인력도 없다. "만든 프로그램이 조직의 자산으로 남으려면, 올리기만 하면 알아서 서비스가 되어야 한다"가 출발점이었다.

## 접근

언어와 무관하게(Python·Node·Go 등) 코드를 **표준 규격**(진입점·포트·헬스체크 계약)으로 감싸면, 플랫폼이 이를 하나의 독립 MSA 서비스로 자동 배포하는 구조를 설계했다.

- **자동 서비스화 파이프라인** — Gitea 레포 등록 → 코드 수집 → 컨테이너화 → Kubernetes 배포로 이어지는 오케스트레이션을 구현했다.
- **인증 마이크로서비스 분리** — 계정을 자체 DB로 단일 소스화한 auth-service를 분리하고(BCrypt 해싱 + HS256 JWT), 플랫폼 backend(MariaDB)와 경계를 나눠 서비스 간 결합을 낮췄다.
- **전 구간 단독 구성** — React+TSX 프론트, Spring Boot 3(Gradle Kotlin DSL) 백엔드, GitHub Actions CI, 부하 테스트(loadtest)까지 전 범위를 직접 구성했다.

## 배운 점과 현재 상태

혼자서 프론트·백엔드·인프라를 모두 책임지면서, 기능 구현보다 **경계 설계**(인증과 플랫폼의 분리, 서비스 간 계약)가 유지보수 비용을 결정한다는 것을 체감했다. 프로젝트는 현재 진행 중이며, 동적으로 생성되는 서비스의 Kubernetes 리소스 격리·회수 정책을 다듬는 것이 다음 과제다.
